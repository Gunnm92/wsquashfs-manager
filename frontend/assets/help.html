Bien démarrer

Ce gestionnaire transforme tes dossiers de jeux Windows en images .wsquashfs, puis t'aide à les régler et à les entretenir. Le lancement lui-même est fait par wsquashfs-launcher, sur chaque client.

  1. CompresserUn dossier de jeu devient une image : un seul fichier compressé, en lecture seule. → Ajouter un jeu
  2. EssayerLe bouton Essai de la fiche lance le jeu sur le client d'essai et rapporte ce qu'il a vu. Ce client se choisit dans le menu d'un client (« Utiliser pour les essais »). → Un jeu ne se lance pas
  3. AjusterLes réglages du jeu sont dans son autorun.cmd, onglet Lancement de la fiche. → Changer un réglage
  4. PartagerEn mode Connecté, les sauvegardes suivent le jeu d'un client à l'autre, et une copie reste sur le manager. → Sauvegardes

Les mots à connaître

Image
Le jeu compressé en un fichier .wsquashfs. Elle n'est jamais modifiée par le jeu.
autorun.cmd
La petite fiche, dans l'image, qui dit quoi lancer et avec quels réglages.
Sauvegardes
Tout ce que le jeu écrit (parties, options), gardé à part dans saves/<jeu>.
Surcharge
Un réglage essayé à côté de l'image, sans la reconstruire. Batocera ne le voit pas.
.old
L'ancienne version d'une image, gardée après une modification jusqu'à ce que tu la supprimes ou la restaures.
Runner
Le Wine ou le Proton qui fait tourner le jeu Windows sous Linux. « Aucun » : choisi par le lanceur ; « custom » : un Wine du client (RUNNER=) ; « intégré » : copié dans l'image.
Prefix
Le dossier de configuration Windows du jeu (registre, fichiers système). Il vient de l'image (wine, proton) ou est créé au lancement (aucun). → Prefix des images
Client
Une machine qui lance les jeux : PC, Steam Deck, AIBox, Batocera… Un client associé partage ses sauvegardes avec le manager. Le client d'essai sert aux lancements d'essai.
Manette
DualSense (manette Sony gérée par le jeu) ou Xbox (vue comme une manette Xbox, comme sous Batocera). → HIDRAW
À traiter
Les pastilles au-dessus de la liste : un compteur par situation à régler (sans version, surcharge à inscrire, ancienne version…). Un clic filtre la liste ; un second clic retire le filtre.
Rien n'est jamais détruit sans confirmation : une image modifiée est reconstruite à côté, et l'ancienne reste en .old tant que tu ne l'as pas supprimée ou restaurée.

L'interface

Trois vues, une seule barre en haut. Les images s'ouvrent dans une fiche à droite, et les réglages ont leur propre page (menu ⚙).

En-tête

  • Sauvegardes · Images · Dossiers : les trois vues. Sauvegardes n'apparaît qu'en mode Connecté (voir Mode dans les réglages).
  • Client affiché (mode Connecté) : « Tous » ou un seul client, et il filtre les vues. Images ne montre que les images installées sur ce client ; Sauvegardes ne montre que les jeux présents sur lui (sans les lignes « Absente »), avec la synchro de ce client. « Tous » montre tout. Le sélecteur est masqué dans Dossiers ; dans Réglages, il désigne le client dont on règle l'essai ou le diagnostic. Le choix reste d'une visite à l'autre.
  • Tâches (bouton à droite) : la file des reconstructions, vérifications et compressions. Un point animé pendant un travail ; un chiffre rouge si une tâche a échoué. Le panneau permet de voir l'état de chaque tâche et d'effacer les terminées (le journal de chaque image est conservé).
  • ⚙ Menu : Réglages (la page des réglages), Actualiser (relit les images ajoutées ou modifiées ; les autres viennent du cache), Aide.

Images

  • Recherche sur le nom, la commande, la version. Filtres : Système, Prefix, Runner, Manette, Extras (touches clavier, relais fakeping). Pour voir les images d'un client, le choisir dans l'en-tête (« Client affiché ») : la liste, son titre et sa taille ne montrent alors que ses images. Si ce client est hors ligne, la liste complète reste affichée avec un bandeau.
  • Pastilles « À traiter » (seulement celles dont le compteur n'est pas nul) : sans version, surcharge à inscrire, ancienne version à supprimer ou restaurer, en cours, sans autorun, tâche en échec. Elles comptent les images du client choisi.
  • Colonnes de la liste : Jeu (avec la version), Prefix (Wine, Proton, Aucun), Réglages (pastilles : DualSense, runner custom ou intégré, touches clavier, relais fakeping, surcharge en attente), Taille, Sauveg. (taille des sauvegardes), État. Un clic sur un en-tête trie.
  • Affichage : liste ou jaquettes (boutons à droite de la barre de recherche).
  • Sélection : cocher une ou plusieurs images. La barre du bas propose Autorun (pour toutes), Fichiers et registre, Vérifier, Illustration (ajouter, ou remplacer), supprimer les anciennes versions (.old), inscrire les surcharges, réinitialiser les sauvegardes, Installer sur… / Désinstaller de… (mode Connecté).

La fiche d'une image

  • En-tête : illustration (son badge ouvre « Ajouter ou remplacer »), nom, état. La fermeture est le ✕.
  • Boutons : Essai (lance le jeu sur le client d'essai, l'observe, l'arrête : tient-il, fenêtre, erreurs, capture ; la flèche à côté règle la durée, 30 s, 60 s ou 2 min) ; Vérifier (intégrité de l'image) ; … (voir plus bas).
  • Menu … : Modifier l'autorun, Nouvelle version…, Ajouter ou remplacer l'illustration, Supprimer ou Restaurer l'ancienne version (si elle existe), Copier les sauvegardes (mode Connecté, avec un client d'essai), Réinitialiser les sauvegardes.
  • Aperçu : trois cartes (Sauvegardes, Lancement, Image) et la ligne Installé sur avec Installer sur… / Désinstaller de…. Un champ vide est masqué et listé en note.
  • Sauveg. : état des sauvegardes de ce jeu, synchroniser, copier, voir dans Sauvegardes. Zone sensible en bas : Réinitialiser (les sauvegardes sont mises de côté, pas supprimées).
  • Lancement : l'autorun lu ou modifié (voir Réglages de l'autorun), la Surcharge s'il y en a une, et Liens du runner (Analyser). Le bouton Modifier ouvre le formulaire (ou le texte brut).
  • Fichiers : les fichiers internes de l'image, avec recherche. Journal : l'historique des tâches de cette image.

Modifier l'autorun

  • Formulaire ou Texte brut (fins de ligne CRLF ou LF). Ajouter une clé propose les clés reconnues.
  • ✦ Proposer : analyse les exécutables de l'image et propose un autorun, avec la raison de chaque réglage.
  • Contrôler (bouclier) : vérifie sans rien écrire. Annuler (flèche) : abandonne les modifications. Mémoriser (signet) : garde ces réglages pour ce jeu, appliqués aux prochaines propositions.
  • Comment appliquer : Surcharge (écrit à côté de l'image, effet au prochain lancement, sans reconstruction) ou Reconstruire l'image (définitif, l'original est gardé en .old). Le bouton de moment (éclair, lune) choisit maintenant ou cette nuit.

Installer sur un client

  • Depuis la fiche (Installé sur) ou la barre de sélection, Installer sur… copie le fichier .wsquashfs dans le dossier des jeux du client choisi. Un envoi coupé reprend où il s'est arrêté.
  • Désinstaller de… retire l'image du client : elle reste dans la bibliothèque du manager.
  • Le client doit être associé et joignable (voir Associer un client).

Dossiers

  • Les dossiers de jeux à compresser, avec leur système et leur contenu (autorun.cmd, image .wsquashfs).
  • État : À faire (pas d'autorun), À traiter (autorun présent, prêt à compresser), En attente et En cours (compression), Fait (image créée). Pastilles de filtre : à faire, à traiter, faits.
  • Analyser et compresser… (après sélection) : chaque dossier reçoit un autorun proposé et justifié, modifiable, puis l'image est créée. Options : renommer .pc en .wine, supprimer le dossier après vérification (jamais avant).
  • Supprimer les dossiers déjà compressés : seulement ceux dont l'image existe, vérifiée avant.

Configuration

  • Les réglages communs du lanceur (DXVK, FSR4, NVAPI, WINE…) s'appliquent à toutes les images d'une machine ou d'une plateforme, sans toucher à chaque autorun.cmd. L'ordre, du plus faible au plus fort : défauts du lanceur, machine, plateforme, image, surcharge du jeu.
  • Machines : le fichier ~/.config/wsquashfs/defaults.autorun du client, lu et écrit par son agent. Les variables WSQUASHFS_* posées sur le client l'emportent sur ce fichier : la fiche les signale.
  • Plateformes : _defaults.autorun dans le dossier du système (roms/<système>/). Il est lu à côté de l'image : un jeu installé sur un client ne le voit pas.
  • Modèle OptiScaler (optiscaler.ini, _optiscaler.ini) : l'onglet OptiScaler.ini ne garde que ce qui diffère du modèle complet installé sur le client (modèle partiel). Le lanceur l'applique une fois, quand il copie l'OptiScaler.ini dans un jeu qui n'en a pas : les jeux qui l'ont déjà ne sont pas modifiés.
  • Préréglages (AMD, NVIDIA, Génération d'images) remplissent le formulaire sans rien enregistrer. Enregistrer affiche d'abord les changements, puis écrit.
  • Une machine dont le lanceur est trop ancien affiche « lanceur trop ancien sur ce client : le mettre à jour » : mets-le à jour (wsquashfs-launcher --update) puis relance son agent.

Réglages

Menu ⚙ › Réglages. Une page avec un sommaire à gauche. Les modifications attendent le bouton Enregistrer (barre du bas) ; Annuler rétablit l'état précédent.

Mode
Autonome : construire et maintenir les images, sans client ni sauvegardes. Connecté : sauvegardes entre clients, installation et lancement d'essai.
Sauvegardes
Synchronisation automatique (jamais, 10 min, 1 h, 6 h) : les clients à synchro auto activée et en retard reçoivent la version du manager. Adresse du manager pour les clients : https://hôte:port par laquelle les clients le joignent ; déclarée à chaque client associé ; vide : pas de synchro automatique.
Clients
Les clients associés (icône, état, en jeu avec le jeu en cours, manettes branchées en infobulle, version du lanceur), dans l'ordre choisi avec les flèches ▲ ▼ de chaque ligne : c'est l'ordre du bandeau. Associer un client : code wsq://… à coller. Le menu d'un client : Utiliser pour les essais, Diagnostic et Maintenance (client d'essai), icône, Dossiers synchronisés, Oublier ce client.
Bibliothèque
Les systèmes pris en compte dans la liste des images. Tout le dossier lit aussi les systèmes ajoutés plus tard ; Choisir les systèmes ne lit que les cochés (avancé : dossiers de base, autres dossiers hors du dossier des roms).
Tâches
Plage de nuit : une tâche « cette nuit » ne démarre que dans cette plage. Tâches en parallèle et délai de conservation des anciennes versions (.old) : fixés au démarrage du manager.
Illustrations
Clé API SteamGridDB (Tester la vérifie ; vide : la clé enregistrée reste), auteurs préférés (passent en premier), seuil de rondeur des icônes.
Lancement d'essai
Le client d'essai (se choisit dans le menu d'un client) et la durée par défaut de l'essai : 30 s, 60 s ou 2 min. Modifiable au moment du lancement, dans la fiche.
Diagnostic
Le résultat de --doctor sur le client d'essai, avec son âge. Relancer le diagnostic le refait.
Serveur
Lecture seule : adresse et réglages au démarrage, fixés par les variables WSQUASHFS_MGR_* (voir le README).

Guides

Les tâches courantes, étape par étape. Clique sur un guide pour l'ouvrir.

Ajouter un jeu
  1. Copier le dossier du jeu dans roms/<système>/, nommé Mon Jeu.pc (ou .wine s'il contient déjà un prefix Wine).
  2. Facultatif : l'essayer avant de le compresser avec wsquashfs-launcher "Mon Jeu.pc". Un dossier .pc est monté comme le sera son image : il n'est jamais modifié, prefix et sauvegardes vont dans les sauvegardes de Mon Jeu, reprises ensuite par l'image.
  3. Ouvrir la vue Dossiers, cocher le dossier puis Analyser et compresser….
  4. Relire l'autorun proposé : l'exécutable choisi et la raison de chaque réglage sont indiqués. Corriger si besoin.
  5. Lancer : la tâche part dans la file (ou cette nuit). L'image est vérifiée à la fin ; le dossier est renommé en .wine, et supprimé seulement si tu l'as demandé.
Un jeu ne se lance pas
  1. Fiche du jeu → Essai : le jeu démarre sur le client d'essai (menu d'un client, « Utiliser pour les essais »), puis le rapport donne les fenêtres ouvertes, les erreurs reconnues et une capture. La durée se règle à côté du bouton.
  2. Message failed to open umu.exe ? Fiche → onglet Lancement → Liens du runner → Analyser : la réparation est proposée.
  3. Chercher l'erreur dans Dépannage.
  4. Essayer un autre réglage (guide suivant) : par exemple WINE=system pour un vieux jeu 32 bits, ou DXVK=0 pour un problème d'affichage.
Changer un réglage d'un jeu
  1. Fiche du jeu → onglet Lancement → Modifier (ou menu … → Modifier l'autorun). Le panneau passe en édition : rien n'est écrit tant que tu n'enregistres pas.
  2. Modifier une valeur, ou Ajouter une clé. Chaque réglage est expliqué dans Réglages de l'autorun. Contrôler vérifie l'ensemble sans rien écrire.
  3. Choisir Surcharge : le réglage s'applique au prochain lancement, en quelques secondes, sans reconstruire. Batocera, lui, ne le voit pas.
  4. Quand le jeu marche : Inscrire dans l'image (ou Reconstruire l'image) pour inscrire le réglage dedans. L'ancienne image est gardée en .old.
Mettre une illustration
  1. Fiche du jeu → badge d'illustration (ou menu … → Ajouter l'illustration). Pour plusieurs images : les cocher, puis Ajouter l'illustration dans la barre de sélection.
  2. Choisir dans l'aperçu et la galerie SteamGridDB. Une clé API doit être enregistrée (Réglages → Illustrations).
  3. Ajouter ne reconstruit pas les images : seules celles qui n'ont pas encore d'illustration sont touchées.
  4. Remplacer reconstruit l'image : l'original est gardé en .old.
Installer un jeu sur un client
  1. Mode Connecté, client associé et joignable (voir Associer un client).
  2. Cocher l'image (ou ouvrir la fiche), puis Installer sur… ; cocher le ou les clients.
  3. Le jeu est copié dans le dossier des jeux du client. Ajouter ensuite le jeu à Steam ou à son lanceur, à la main.
  4. Pour retirer l'image d'un client : Désinstaller de…. Elle reste dans la bibliothèque du manager.
Installer une nouvelle version ou un patch
  1. Déposer la nouvelle version (ou le patch) dans un dossier du serveur.
  2. Fiche du jeu → menu … → Nouvelle version… (ou le lien Mettre à jour dans l'aperçu), indiquer ce dossier.
  3. Aperçu : la liste des fichiers ajoutés, remplacés et supprimés, et la place disque nécessaire.
  4. Mettre à jour. L'ancienne image est gardée en .old.
Supprimer ou restaurer l'ancienne version (.old)
  1. Après une reconstruction ou une mise à jour, la fiche affiche « Une ancienne version est conservée », et la pastille ancienne version à supprimer ou restaurer apparaît dans la liste.
  2. Lancer le jeu pour vérifier qu'il marche toujours.
  3. Supprimer l'ancienne version l'efface définitivement ; Restaurer l'ancienne version remet l'image d'avant la modification (la reconstruction est perdue).
  4. Pour plusieurs jeux à la fois : les sélectionner, puis Supprimer les anciennes versions (.old) (confirmation avec le nombre d'images et la place libérée).
Faire le travail pendant la nuit
  1. À côté de chaque bouton qui lance un travail, une petite icône indique quand : éclair = tout de suite, lune = cette nuit. Un clic bascule.
  2. La plage de nuit se règle dans Réglages, section « Tâches » (« Plage de nuit »).
  3. Une tâche prévue la nuit peut être lancée tout de suite depuis le bouton Tâches, en haut à droite.

Sauvegardes

La vue Sauvegardes garde les mêmes parties sur tous tes clients (PC, Steam Deck, AIBox…). Le manager en garde aussi une copie, disponible même quand un client est éteint. Elle n'existe qu'en mode Connecté.

Associer un client
  1. Sur le client : wsquashfs-launcher --pair. Il affiche un code wsq://…, valable une seule fois et 10 minutes.
  2. Ici : ⚙ › Réglages › Clients › Associer un client, puis coller ce code. (Le bouton est aussi proposé depuis la vue Sauvegardes quand aucun client n'est associé.)
  3. Sur le client : wsquashfs-launcher --agent, pour qu'il reste joignable. L'agent ne démarre jamais tout seul.

Les clients

  • Un bouton par client dans l'en-tête (Tous ou un client), avec son icône et son état : joignable, hors ligne, ou en jeu (pastille bleue et ▶, jeu en cours à droite). Les parties lancées et terminées s'affichent en message ; une sortie en erreur au bout de moins d'une minute est signalée. Le manager est sa propre copie.
  • Un client hors ligne (éteint, en veille) reste visible, mais ce que le manager sait de lui vient de la dernière synchro.
  • Menu du client (chevron) : Utiliser pour les essais (client d'essai du lancement), Diagnostic du lanceur… et Maintenance… (pour le client d'essai), l'icône (détectée ou choisie : Linux, SteamOS, SteamBox, Batocera), Dossiers synchronisés…, Mettre à jour le lanceur… (agent 11 : binaire publié vérifié par son empreinte, l'agent redémarre), Oublier ce client (sauf le client d'essai du lanceur local).
  • Maintenance… lance sur le client d'essai : lister les jeux, démonter, nettoyer, copier les sauvegardes de tous les jeux, synchroniser, état de la synchro. Chaque action demande confirmation, sauf les actions de lecture.

Lire la liste

Une ligne par jeu, en sections par plateforme : Jeux PC, puis les autres systèmes Batocera où se trouve l'image (Arcade PC, Taito Type X²…), Switch, Dossiers, et Autres (image introuvable). Un clic sur le titre d'une section la replie ou la rouvre. Chaque ligne donne :

Jeu
Le nom (avec sa vignette). Les dossiers déclarés et les jeux Switch portent leur nom de synchro.
Taille
Taille de la sauvegarde la plus récente, sur le client choisi ou sur le manager.
Dernière partie
Date de cette sauvegarde, et l'endroit où elle se trouve (« sur le manager », nom du client).
À jour
Toutes les copies présentes sont à jour : rien à faire.
À envoyer
Le client est en avance sur le manager : sa copie remonte au manager (bouton Envoyer au manager).
À récupérer
Le client est en retard : il peut recevoir la version du manager (bouton Récupérer du manager).
Conflit
Le client et le manager ont tous deux changé depuis leur dernier échange. Rien n'est écrasé : les deux versions sont gardées sur le manager, et le bouton Départager… ouvre la fenêtre où tu choisis celle à conserver (l'autre reste archivée).
Non partagée
Une seule copie existe : aucun autre client ne la partage.
Absente
Le client choisi n'a pas ce jeu. Ce n'est pas une différence : il n'est pas touché. Il s'installe depuis le menu de la ligne.
Hors ligne
Le client ne répond pas (éteint, agent arrêté) : rien ne peut lui être envoyé avant son retour.

Au-dessus de la liste : la recherche (Jeu…) et les pastilles À traiter : Conflits et À synchroniser, qui ne gardent que les lignes concernées. Une info-bulle sur la pastille Synchro donne le détail (et signale à vérifier quand la copie la plus lourde n'est pas la plus récente).

Synchroniser

  • Bouton de la ligne (Envoyer au manager, Récupérer du manager, Départager…) : fait l'action proposée pour ce jeu, dans le sens indiqué par l'info-bulle.
  • ⋯ de la ligne : copier vers le manager, installer sur un client qui n'a pas le jeu, Supprimer…, et les autres actions du jeu.
  • Plusieurs jeux : les cocher. La barre du bas choisit la source (la plus avancée, jeu par jeu ; un client ; le manager) et les cibles (cases dans un menu), puis Synchroniser (récapitulatif avant envoi), Copier vers le manager ou Supprimer….
Rien n'est perdu : la version remplacée est archivée sur le client, et le manager garde ses 3 versions précédentes. Le jeu doit être arrêté : un client où il tourne n'est pas touché, le résultat le dit.

Autres sauvegardes : dossiers et Switch

  • Dossier déclaré : un dossier quelconque (sauvegardes d'un autre émulateur, d'un jeu Linux…) synchronisé comme un jeu. Le déclarer sur un client : menu du client → Dossiers synchronisés…, ou wsquashfs-launcher --sync dir add <nom> <chemin> sur le client (chemin à partir du dossier personnel, ex. .local/share/hookshot/save). Il se propage ensuite comme une sauvegarde, au même chemin chez les autres clients qui le déclarent.
  • Jeux Switch (Eden) : rien à déclarer. Les sauvegardes d'Eden sont synchronisées jeu par jeu (section Switch) ; chaque client les reçoit dans son propre profil Eden. Eden doit être fermé pendant la synchro. Sur un client neuf, lancer Eden une fois avant de recevoir.

Supprimer

Supprimer… ouvre une case par client joignable et une pour le manager. Sur un client, la sauvegarde est archivée dans son dossier des backups avant d'être effacée ; sur le manager, la version courante devient une version datée.

Synchro automatique

Quand le manager est joignable, un client lui envoie sa partie à la sortie d'un jeu : rien n'est récupéré au lancement. Sur chaque client, wsquashfs-launcher --sync auto on l'active (--sync auto off l'arrête). Le manager doit être atteignable à l'adresse réglée dans Réglages → Sauvegardes (« Adresse du manager pour les clients ») ; s'il ne répond pas, la partie reste sur le client et une ligne le dit.

À l'intervalle choisi dans Réglages → Sauvegardes (jamais, 10 min, 1 h, 6 h), les clients à synchro auto activée qui sont en avance remontent d'abord leur copie au manager, puis les clients en retard reçoivent la version du manager ; leur agent doit être lancé. Si le client et le manager ont tous deux changé, rien n'est écrasé : le jeu passe en Conflit, les deux versions sont gardées, à toi de les départager.

Rien n'est perdu : la version que le manager remplace est archivée (il garde 3 versions). Hors synchro automatique, rien ne revient vers le client : pour récupérer une partie du manager, c'est Synchroniser ou --sync.

En ligne de commande

Sans le manager, wsquashfs-launcher --sync synchronise à la main avec les autres clients du réseau local (--sync status montre ce qui serait fait). Même règle : la plus lourde gagne, l'autre est archivée. Le détail des commandes est dans Le lanceur.

Prefix des images

Le prefix d'une image dépend de ce qui se trouve à sa racine. Il décide du runner utilisé par défaut. La colonne Prefix de la liste (et son filtre) affiche Wine, Proton ou Aucun.

Prefix wine (Batocera)

Le format de Batocera : jeux arcade et jeux PC préparés pour lui, avec leur prefix Wine complet. L'image reste lisible par Batocera telle quelle.

MonJeu.wine/
├── autorun.cmd
├── system.reg  user.reg
└── drive_c/MonJeu/game.exe
DIR=drive_c/MonJeu
CMD=game.exe
En savoir plus
  • Runner : wine-tkg par défaut. WINE=system pour un jeu 32 bits qui échoue sous wine-tkg (non WoW64) mais passe avec le Wine WoW64 du système.
  • La racine de l'image est le prefix : DIR est relatif à cette racine.
  • Des fichiers *.reg à la racine sont importés au lancement.
  • Batocera ignore les clés qu'il ne connaît pas (GAME_VERSION, WINE…).

Prefix proton

Un prefix créé par Heroic, Steam ou umu : jeux PC récents. Le jeu est lancé par le même Proton, via umu.

MonJeu.wine/
├── autorun.cmd
├── config_info  pfx -> .
└── drive_c/MonJeu/Bin/game.exe
DIR=drive_c/MonJeu/Bin
CMD=game.exe
En savoir plus
  • Runner : le Proton qui a créé le prefix (1re ligne de config_info), sinon le repli décrit dans Choix automatique du runner.
  • PROTON=<nom> impose un Proton ; s'il est introuvable, c'est une erreur, sans repli silencieux.
  • Les DLL de Proton sont des liens vers le runner (PROTON_DLL_COPY vide), pas des copies.
  • Batocera n'a pas umu : ces images n'y sont pas prévues.

Aucun prefix : jeu seul

Seulement les fichiers du jeu. Le prefix est créé au premier lancement, dans les sauvegardes : l'image reste légère.

MonJeu/
├── autorun.cmd
└── game/run me.exe
CMD="game/run me.exe" --arg
En savoir plus
  • Le prefix est créé par Proton via umu (proton-cachyos, sinon l'UMU-Proton le plus récent, sinon GE-Proton).
  • CMD est relatif à la racine ; guillemets si le chemin contient des espaces.
  • WINE=tkg pour garder un prefix Wine. Un prefix Wine déjà présent dans les sauvegardes reste sous Wine : réinitialiser les sauvegardes du jeu pour passer sous Proton.

Runner intégré à l'image

Pour un jeu qui ne marche qu'avec un runner précis (Proton modifié pour lui, Wine particulier d'un jeu arcade) : le runner est copié dans l'image, qui devient autonome. Possible avec les trois types. Dans la liste, la colonne Réglages affiche intégré ; le filtre Runner distingue aucun, custom (un Wine du client) et intégré.

MonJeu.wine/
├── autorun.cmd
├── runners/Proton-MonJeu-11.0/
└── drive_c/ …
PROTON=Proton-MonJeu-11.0
À réserver aux runners propres à un jeu. Un Proton standard (UMU-Proton, GE-Proton, proton-cachyos) n'a pas à être intégré : compter ~250 Mo de plus par image.
Comment le runner est choisi
  • PROTON=<nom> ou WINE=<nom> cherchent d'abord runners/<nom>/ (aussi runners/wine-<nom>/, casse ignorée), puis les runners du client. Sans clé, un runner seul dans runners/ est utilisé.
  • Priorité : --wine > runner intégré > runners du client.
  • Runner nommé introuvable : le lancement s'arrête avec un message, le jeu ne part pas sous un autre runner.
  • Utilisé en lecture seule depuis l'image : Proton n'écrit rien dans les sauvegardes.
  • RUNNER= ne sert qu'aux chemins absolus du client.
  • Batocera ignore runners/.
Liens du prefix (erreur failed to open umu.exe)

Dans un prefix Proton, les DLL de Wine sont des liens vers le runner. Ils doivent pointer en relatif dans runners/<nom>/ (ex. ../../../runners/<nom>/files/lib/wine/…). Un lien vers un autre emplacement est cassé ailleurs, et Proton ne le répare pas.

L'onglet « Dossiers » réécrit ces liens tout seul. Sur une image existante : fiche → onglet Lancement → Liens du runner → Analyser, puis la réparation proposée.

À la main : find MonJeu.wine -type l -lname '*compatibilitytools.d*' doit être vide.

Correctif du jeu dans le runner (protonfix)

Un Proton intégré peut porter un protonfix, script Python que Proton exécute avant chaque lancement. GAMEID désigne le script :

runners/<Proton>/protonfixes/gamefixes-umu/umu-monjeu.py
PROTON=<Proton>
ENV=GAMEID=umu-monjeu
  • main() fait la préparation (un sys.exit(1) arrête le lancement), puis peut lancer un fil pour le patch à chaud, qui vit jusqu'à la fin du jeu.
  • N'agir que si l'exécutable du jeu est dans sys.argv : umu sert aussi à d'autres commandes.
  • Pour tout runner, Wine compris : PRE= et ATTACH= de l'autorun.

Réglages de l'autorun

L'autorun.cmd est un fichier texte à la racine de l'image : une ligne RÉGLAGE=valeur par réglage. Seul CMD est obligatoire. Clique sur un réglage pour le détail. Une clé inconnue est conservée, mais ignorée par Batocera et le lanceur.

L'essentiel

CMDLe programme à lancer obligatoire"My Game.exe" -fullscreen

DIRLe dossier du programmedrive_c/Game
Relatif à la racine de l'image. Vide : la racine.
GAME_VERSIONLa version du jeu, pour s'y retrouverv2.1.0 GOG
Affichée au lancement, par --info, --pack, --install et ici. Ignorée par Batocera.

Manettes, langue, environnement

HIDRAWManette Sony gérée par le jeu lui-même1 · bt · 0

Par défaut, la manette est vue comme une manette Xbox, comme sous Batocera. À changer seulement pour un jeu qui gère la DualSense lui-même (sans Steam Input) :

  • 1 : manette Sony par hidraw ; une DualSense Bluetooth est présentée en USB (dualsense-usb-bridge), car certains jeux refusent la Bluetooth. Repli en manette Xbox si illisible.
  • bt : DualSense Bluetooth en direct, pour un jeu dont les vibrations haptiques passent par la Bluetooth.
  • 0 : manette Xbox (le défaut).

Sous GE-Proton, le mode manette Xbox passe aussi par hidraw (PROTON_SONY_HIDRAW_XINPUT=1, posé par le lanceur).

LANGLa langue du jeufr_FR.UTF-8
Posée dans LC_ALL.
ENVVariables d'environnement en plusVAR1=a VAR2=b
Séparées par des espaces. Une surcharge ou un _defaults.autorun ajoute ses variables à celles de l'image au lieu de les remplacer ; -VAR en retire une, ENV= vide les retire toutes. Jamais WINEDLLOVERRIDES : il écraserait les réglages DLL du lanceur.

Touches clavier : un fichier <jeu>.wsquashfs.keys à côté de l'image associe des boutons de manette à des touches.

Pour aller plus loin

Essayer un réglage sans reconstruire (surcharge)

Un fichier <jeu>.wsquashfs.autorun à côté de l'image, au même format. Ses réglages l'emportent sur ceux de l'image ; RÉGLAGE= vide revient au défaut du lanceur. C'est ce qu'écrit le choix Surcharge (« Essayer sans reconstruire ») de l'éditeur d'autorun.

# Le Jeu.wsquashfs.autorun
HIDRAW=1

Batocera ne le lit pas : une fois le réglage validé, reconstruire l'image (ou Inscrire les surcharges sur une sélection, qui reconstruit chaque image puis supprime sa surcharge).

Le lanceur lit aussi, du plus faible au plus fort : ~/.config/wsquashfs/defaults.autorun (le client), les variables WSQUASHFS_*, _defaults.autorun dans le dossier du jeu (tous les jeux du dossier), l'autorun.cmd de l'image, la surcharge, puis --set RÉGLAGE=valeur. wsquashfs-launcher --show <jeu> donne la valeur finale de chaque réglage et sa provenance.

Mémoriser des réglages pour un jeu

Le signet de l'éditeur d'autorun enregistre les réglages choisis pour ce jeu. Les prochaines propositions (✦ Proposer) les appliquent à la place du choix automatique.

Choix automatique du runner

Sans WINE, PROTON, RUNNER, runner intégré ni --wine :

  • Prefix proton : la même version de Proton (Heroic, Steam, /usr/share/steam/compatibilitytools.d), sinon proton-cachyos, puis l'UMU-Proton le plus récent, puis GE-Proton, puis n'importe quel Proton. Lancé via umu, comme Heroic ; sans umu, le Wine du Proton est lancé directement (WSQUASHFS_UMU=0 force ce mode).
  • Aucun prefix (jeu seul) : proton-cachyos, sinon UMU-Proton, sinon GE-Proton. Les deux premiers gèrent la DualSense en manette Xbox avec vibrations ; GE-Proton la force en hidraw.
  • Autres prefixes (arcade Batocera) : wine-tkg, puis wine-ge/lutris, puis wine-proton, puis le Wine du système.

Les DLL que Proton copie d'ordinaire dans chaque prefix (~190 Mo par jeu) y sont des liens ; ENV=PROTON_DLL_COPY=<motifs> pour un jeu qui doit les remplacer. Le lanceur ramène la pile à 8 Mo si elle est illimitée (Docker sur Unraid), sans quoi proton-cachyos ne démarre pas.

Fonctionnement

Modes de montage

Choisis automatiquement à chaque lancement :

  • overlay noyau (par défaut) : overlay du noyau dans un namespace utilisateur ; lectures aléatoires environ 5 fois plus rapides, rien d'orphelin après un plantage. Requiert Linux ≥ 5.11 et squashfuse ≥ 0.5.
  • overlay FUSE (repli, et --mount) : squashfuse + fuse-overlayfs.
  • copy : FUSE bloqué (conteneur sans CAP_SYS_ADMIN) ; copie de travail en cache.
  • dossier : prefix .wine ou jeu installé par --install, lancé sur place. Un dossier .pc passe, lui, par l'overlay FUSE.

Tout échec de l'overlay noyau retombe sur fuse-overlayfs ; --doctor dit pourquoi. Les deux partagent les mêmes sauvegardes.

Où sont les données

├── backups/         archives de --erase
└── wine/ dxvk/ …    runners et traducteurs installés

~/.config/wsquashfs/ defaults.autorun (réglages de la machine)

À côté de l'image : <jeu>.wsquashfs.autorun (surcharge) et <jeu>.wsquashfs.keys (touches). À côté de roms/ : saves/<système>/<jeu>.

Installer le lanceur sur un PC 
curl -fsSL https://raw.githubusercontent.com/Gunnm92/wsquashfs-launcher/main/install.sh | bash

Pour Debian/Ubuntu et Arch (CachyOS, Manjaro, EndeavourOS) : installe les paquets manquants, propose wine-tkg, umu-run et un Proton, DXVK, VKD3D-Proton et d7vk, puis termine par --doctor. Le script ne fait que télécharger le lanceur s'il est absent : l'installation est faite par le lanceur lui-même (wsquashfs-launcher --setup, voir le tableau), la mise à jour par --update.

Pegasus et EmulationStation

Commande de lancement : wsquashfs-launcher "{file.path}".

Pegasus (metadata.pegasus.txt)
collection: Windows Games (WSquashFS)
extensions: wsquashfs
launch: wsquashfs-launcher "{file.path}"
EmulationStation (es_systems.cfg)
<extension>.wsquashfs</extension>
<command>wsquashfs-launcher %ROM%</command>

Dépannage

Les problèmes fréquents et leur solution. Pour un jeu qui ne démarre pas, commence par le guide.

Le jeu ne se lance pas
Fiche → Essai : rapport avec fenêtres, erreurs et capture. En ligne de commande : relancer depuis un terminal pour lire les erreurs Wine, et vérifier la commande avec --info.
failed to open umu.exe
Les liens du prefix pointent vers un runner absent. Fiche → onglet Lancement → Liens du runner → Analyser, puis la réparation proposée. Voir Runner intégré.
fusermount3: mount failed: Operation not permitted
FUSE est bloqué dans le conteneur : le lanceur passe en mode copy (plus lent au premier lancement). Pour l'overlay : --device /dev/fuse --cap-add SYS_ADMIN.
Overlay noyau indisponible
Le jeu marche quand même, sous fuse-overlayfs. --doctor donne la cause : squashfuse antérieur à 0.5 (Debian 12), namespaces refusés (seccomp de Docker : --security-opt seccomp=unconfined ; AppArmor d'Ubuntu 24.04 ; user.max_user_namespaces=0), ou sauvegardes sur un système de fichiers sans attributs user.*.
Make sure that your X server is running…
Wine ne trouve pas l'affichage : vérifier $DISPLAY et autoriser l'utilisateur avec xhost +SI:localuser:$(id -un).
Écran noir ou affichage très lent
Essayer DXVK=0 (vieux jeux Direct3D) ou VIRTUAL_DESKTOP=1920x1080 (jeu qui change la résolution), d'abord avec une surcharge (« Essayer sans reconstruire »).
Vieux jeu 32 bits qui plante au démarrage
wine-tkg n'est pas WoW64 : essayer WINE=system (le Wine WoW64 du système), éventuellement avec ARCH=win32.
Jeu arcade réseau : socket ICMP refusé (SOCK_RAW)
Le jeu vérifie la connexion par un « ping » que le conteneur refuse. Le relais fakeping (dinput8.dll) rend un ping sans réponse au lieu d'une erreur : sélectionner le jeu (ou les jeux) → Fichiers dans la barre de sélection → préréglage relais fakeping, qui demande le chemin du fichier dinput8.dll sur le serveur.
Un jeu reste monté
wsquashfs-launcher --umount démonte tous les jeux. Sur un client d'essai, Maintenance… (menu du client) propose la même action, après confirmation.
Repartir de zéro pour un jeu
Fiche → menu … → Réinitialiser les sauvegardes : elles sont mises de côté (renommées), pas supprimées. En ligne de commande : --erase "MonJeu" (archive drive_c/users, puis efface tout) ; --clear "MonJeu" ne garde que drive_c/users.
Le client n'apparaît pas, ou reste hors ligne
Sur le client, wsquashfs-launcher --agent status : si l'agent ne tourne pas, --agent. Vérifier que le client et le manager se joignent à l'adresse réglée dans Réglages → Sauvegardes. Une association se fait avec un code neuf (--pair), valable 10 minutes.
Une sauvegarde est marquée Conflit
Le client et le manager ont tous deux changé depuis leur dernier échange : les deux versions sont gardées et rien n'est écrasé. Bouton Départager… de la ligne : choisis la version à conserver. Le jeu doit être arrêté des deux côtés.
L'icône de zone de notification ne s'affiche pas (--tray)
L'icône a besoin d'une session graphique avec un bus D-Bus de session. Lancer la commande depuis le bureau (pas en SSH sans session), puis --tray dit ce qui manque. Journal : tray.log à côté de celui de l'agent.
La complétion (Tab) ne marche pas
Lancer wsquashfs-launcher --setup (la complétion bash est proposée), puis ouvrir un nouveau terminal. Hors bash, elle n'est pas installée.
