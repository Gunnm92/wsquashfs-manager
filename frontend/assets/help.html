Bien démarrer

Ce gestionnaire transforme tes dossiers de jeux Windows en images .wsquashfs, puis t'aide à les régler et à les entretenir. Le lancement lui-même est fait par wsquashfs-launcher.

  1. EmpaqueterUn dossier de jeu devient une image : un seul fichier compressé, en lecture seule. → Ajouter un jeu
  2. EssayerLe lancement d'essai démarre le jeu sur le client d'essai et rapporte ce qu'il a vu (à choisir dans le bandeau Clients : « Utiliser pour les essais »). → Un jeu ne se lance pas
  3. AjusterLes réglages du jeu sont dans son autorun.cmd, modifiable depuis la fiche. → Changer un réglage

Les mots à connaître

Image
Le jeu compressé en un fichier .wsquashfs. Elle n'est jamais modifiée par le jeu.
autorun.cmd
La petite fiche, dans l'image, qui dit quoi lancer et avec quels réglages.
Sauvegardes
Tout ce que le jeu écrit (parties, options), gardé à part dans saves/<jeu>.
Surcharge
Un réglage essayé à côté de l'image, sans la reconstruire. Batocera ne le voit pas.
.old
L'ancienne version d'une image, gardée après une modification jusqu'à ce que tu la supprimes ou la restaures.
Runner
Le Wine ou le Proton qui fait tourner le jeu Windows sous Linux.
Rien n'est jamais détruit sans confirmation : une image modifiée est reconstruite à côté, et l'ancienne reste en .old tant que tu ne l'as pas supprimée ou restaurée.

Guides

Les tâches courantes, étape par étape. Clique sur un guide pour l'ouvrir.

Ajouter un jeu
  1. Copier le dossier du jeu dans roms/<système>/, nommé Mon Jeu.pc (ou .wine s'il contient déjà un prefix Wine).
  2. Facultatif : l'essayer avant de l'empaqueter avec wsquashfs-launcher "Mon Jeu.pc". Un dossier .pc est monté comme le sera son image : il n'est jamais modifié, prefix et sauvegardes vont dans les sauvegardes de Mon Jeu, reprises ensuite par l'image.
  3. Ouvrir l'onglet Dossiers, cocher le dossier puis Analyser et empaqueter.
  4. Relire l'autorun proposé : l'exécutable choisi et la raison de chaque réglage sont indiqués. Corriger si besoin.
  5. Empaqueter : la tâche part dans la file (ou cette nuit). L'image est vérifiée à la fin ; le dossier est renommé en .wine, et supprimé seulement si tu l'as demandé.
Un jeu ne se lance pas
  1. Fiche du jeu → Lancement d'essai : le jeu démarre sur le client d'essai (bandeau Clients, « Utiliser pour les essais »), puis le rapport donne les fenêtres ouvertes, les erreurs reconnues et une capture.
  2. Message failed to open umu.exe ? Fiche → Infos → Liens du runner → Analyser : la réparation est proposée.
  3. Chercher l'erreur dans Dépannage.
  4. Essayer un autre réglage (guide suivant) : par exemple WINE=system pour un vieux jeu 32 bits, ou DXVK=0 pour un problème d'affichage.
Changer un réglage d'un jeu
  1. Fiche du jeu → Modifier l'autorun. La fiche passe en mode édition (cadre orange) : rien n'est écrit tant que tu n'enregistres pas.
  2. Modifier une valeur, ou Ajouter un réglage. Chaque réglage est expliqué dans Réglages de l'autorun.
  3. Essayer sans reconstruire : le réglage s'applique au prochain lancement, en quelques secondes. Batocera, lui, ne le voit pas.
  4. Quand le jeu marche : Reconstruire l'image pour inscrire le réglage dedans. L'ancienne image est gardée en .old.
Installer une nouvelle version ou un patch
  1. Déposer la nouvelle version (ou le patch) dans un dossier du serveur.
  2. Fiche du jeu → Nouvelle version, indiquer ce dossier.
  3. Aperçu : la liste des fichiers ajoutés, remplacés et supprimés, et la place disque nécessaire.
  4. Mettre à jour. L'ancienne image est gardée en .old.
Supprimer ou restaurer l'ancienne version (.old)
  1. Après une reconstruction ou une mise à jour, la fiche affiche « Une ancienne version est conservée ».
  2. Lancer le jeu pour vérifier qu'il marche toujours.
  3. Supprimer l'ancienne version l'efface définitivement ; Restaurer l'ancienne version remet l'image d'avant la modification.
  4. Pour plusieurs jeux à la fois : les sélectionner, puis Supprimer les anciennes versions (.old) (confirmation avec le nombre d'images).
Faire le travail pendant la nuit
  1. À côté de chaque bouton qui lance un travail, une petite icône indique quand : éclair = tout de suite, lune = cette nuit. Un clic bascule.
  2. La plage de nuit se règle dans Réglages, section « Tâches de nuit ».
  3. Une tâche prévue la nuit peut être lancée tout de suite depuis Tâches, en haut à droite.

Sauvegardes

L'onglet Sauvegardes garde les mêmes parties sur toutes tes clients (PC, Steam Deck, AIBox…). Le manager en garde aussi une copie, disponible même quand un client est éteint.

Associer un client
  1. Sur le client : wsquashfs-launcher --pair. Il affiche un code wsq://…, valable une seule fois.
  2. Ici : Associer un client, puis coller ce code.
  3. Sur le client : wsquashfs-launcher --agent, pour qu'il reste joignable. L'agent ne démarre jamais tout seul.

Le bandeau des clients

  • Une carte par client : icône, pastille verte (joignable) ou rouge (injoignable), nombre de jeux. La carte Manager est sa copie.
  • Un client injoignable (éteint, en veille) reste dans le bandeau, en rouge, mais n'a pas de colonne dans le tableau.
  • Clic sur une carte : n'affiche que les sauvegardes de ce client, sa colonne en premier. Un second clic affiche tout.
  • Chevron à droite de la carte : changer l'icône, ou Oublier ce client (pas le client d'essai, qui se choisit dans « Utiliser pour les essais »).

Lire le tableau

Une ligne par jeu, une colonne par client, plus la colonne Manager, en sections par plateforme : Jeux PC, puis les autres systèmes de Batocera où se trouve l'image du jeu (Arcade PC, Taito Type X²…), Switch, Dossiers, et « Autres » quand aucune image n'est trouvée. Un clic sur le titre d'une section la replie (pour n'afficher qu'une plateforme) ou la rouvre. Chaque case donne l'état, la taille et la date :

★ plus avancée
La version la plus récente, parmi celles de taille proche de la plus lourde (moins de 10 % d'écart) : c'est elle que Sync propose d'envoyer.
en retard
Une version plus ancienne, qui recevra la plus avancée.
à départager
Synchro automatique : le client a changé depuis son dernier échange avec le manager. Rien n'est envoyé ; c'est à toi de choisir la version (Sync, ou --sync).
identique
Les clients qui ont le jeu ont la même version : rien à faire.
— absente
Le client n'a pas ce jeu. Ce n'est pas une différence : il n'est pas touché.
? injoignable
Le client ne répond pas (éteint, agent arrêté) : il ne compte pas.
⚠ à vérifier
Une version plus récente mais nettement plus petite existe ailleurs : vérifier avant de synchroniser.

Filtres au-dessus du tableau : Tous, Différences, Identiques, Sur le manager.

Synchroniser

  • Sync sur une ligne : envoie la version la plus avancée vers les clients en retard.
  • Le chevron de la ligne propose aussi : sync depuis un client précis, Installer sur… un client qui n'a pas le jeu, Copier vers le manager, Sync depuis le manager, et Supprimer….
  • Plusieurs jeux : les cocher. Le bandeau en bas choisit la source (la plus avancée, jeu par jeu ; un client ; le manager) et les cibles, puis Sync (récapitulatif avant envoi), Copier vers le manager ou Supprimer….
Rien n'est perdu : la version remplacée est archivée sur le client, et le manager garde ses 3 versions précédentes. Le jeu doit être arrêté : un client où il tourne n'est pas touché, le résultat le dit.

Autres sauvegardes : dossiers et Switch

  • Dossier déclaré : un dossier quelconque (sauvegardes d'un autre émulateur, d'un jeu Linux…) synchronisé comme un jeu. Le déclarer sur un client : chevron de la carte → Dossiers synchronisés…, ou wsquashfs-launcher --sync dir add <nom> <chemin> sur le client (chemin à partir du dossier personnel, ex. .local/share/hookshot/save). Il se propage ensuite comme une sauvegarde : Installer sur… ou Sync vers un client qui ne l'a pas le déclare chez elle, au même chemin.
  • Jeux Switch (Eden) : rien à déclarer. Les sauvegardes d'Eden sont synchronisées jeu par jeu (sous leur nom, dans la section Switch) ; chaque client les reçoit dans son propre profil Eden. Eden doit être fermé pendant la synchro. Sur un client neuf, lancer Eden une fois avant de recevoir.

Supprimer

Supprimer… ouvre une case par client joignable et une pour le manager. Sur un client, la sauvegarde est archivée dans son dossier des backups avant d'être effacée ; sur le manager, la version courante devient une version datée.

Synchro automatique

Quand le manager est joignable, un client lui envoie sa partie à la sortie d'un jeu : rien n'est récupéré au lancement. Sur chaque client, wsquashfs-launcher --sync auto on l'active (--sync auto off l'arrête) ; la carte du client porte alors la pastille auto. Le manager doit être atteignable à l'adresse réglée dans Réglages → Général (port 8790) ; s'il ne répond pas, la partie reste sur le client et une ligne le dit.

Les clients dont la synchro auto est activée reçoivent aussi la version la plus récente du manager, si elles n'ont pas de partie non envoyée ; leur agent doit être lancé. Un client modifié depuis le dernier échange n'est pas écrasée : elle est marquée à départager.

Rien n'est perdu : la version que le manager remplace est archivée (il garde 3 versions). Hors synchro automatique, rien ne revient vers le client : pour récupérer une partie du manager, c'est Sync ou --sync.

En ligne de commande

Sans le manager, wsquashfs-launcher --sync synchronise à la main avec les autres clients du réseau local (--sync status montre ce qui serait fait). Même règle : la plus lourde gagne, l'autre est archivée.

Prefix des images

Le prefix d'une image dépend de ce qui se trouve à sa racine. Il décide du runner utilisé par défaut.

Prefix wine (Batocera)

Le format de Batocera : jeux arcade et jeux PC préparés pour lui, avec leur prefix Wine complet. L'image reste lisible par Batocera telle quelle.

MonJeu.wine/
├── autorun.cmd
├── system.reg  user.reg
└── drive_c/MonJeu/game.exe
DIR=drive_c/MonJeu
CMD=game.exe
En savoir plus
  • Runner : wine-tkg par défaut. WINE=system pour un jeu 32 bits qui échoue sous wine-tkg (non WoW64) mais passe avec le Wine WoW64 du système.
  • La racine de l'image est le prefix : DIR est relatif à cette racine.
  • Des fichiers *.reg à la racine sont importés au lancement.
  • Batocera ignore les clés qu'il ne connaît pas (GAME_VERSION, WINE…).

Prefix proton

Un prefix créé par Heroic, Steam ou umu : jeux PC récents. Le jeu est lancé par le même Proton, via umu.

MonJeu.wine/
├── autorun.cmd
├── config_info  pfx -> .
└── drive_c/MonJeu/Bin/game.exe
DIR=drive_c/MonJeu/Bin
CMD=game.exe
En savoir plus
  • Runner : le Proton qui a créé le prefix (1re ligne de config_info), sinon le repli décrit dans Choix automatique du runner.
  • PROTON=<nom> impose un Proton ; s'il est introuvable, c'est une erreur, sans repli silencieux.
  • Les DLL de Proton sont des liens vers le runner (PROTON_DLL_COPY vide), pas des copies.
  • Batocera n'a pas umu : ces images n'y sont pas prévues.

Aucun prefix : jeu seul

Seulement les fichiers du jeu. Le prefix est créé au premier lancement, dans les sauvegardes : l'image reste légère.

MonJeu/
├── autorun.cmd
└── game/run me.exe
CMD="game/run me.exe" --arg
En savoir plus
  • Le prefix est créé par Proton via umu (proton-cachyos, sinon l'UMU-Proton le plus récent, sinon GE-Proton).
  • CMD est relatif à la racine ; guillemets si le chemin contient des espaces.
  • WINE=tkg pour garder un prefix Wine. Un prefix Wine déjà présent dans les sauvegardes reste sous Wine : réinitialiser les sauvegardes du jeu pour passer sous Proton.

Runner intégré à l'image

Pour un jeu qui ne marche qu'avec un runner précis (Proton modifié pour lui, Wine particulier d'un jeu arcade) : le runner est copié dans l'image, qui devient autonome. Possible avec les trois types.

MonJeu.wine/
├── autorun.cmd
├── runners/Proton-MonJeu-11.0/
└── drive_c/ …
PROTON=Proton-MonJeu-11.0
À réserver aux runners propres à un jeu. Un Proton standard (UMU-Proton, GE-Proton, proton-cachyos) n'a pas à être intégré : compter ~250 Mo de plus par image.
Comment le runner est choisi
  • PROTON=<nom> ou WINE=<nom> cherchent d'abord runners/<nom>/ (aussi runners/wine-<nom>/, casse ignorée), puis les runners du client. Sans clé, un runner seul dans runners/ est utilisé.
  • Priorité : --wine > runner intégré > runners du client.
  • Runner nommé introuvable : le lancement s'arrête avec un message, le jeu ne part pas sous un autre runner.
  • Utilisé en lecture seule depuis l'image : Proton n'écrit rien dans les sauvegardes.
  • RUNNER= ne sert qu'aux chemins absolus du client.
  • Batocera ignore runners/.
Liens du prefix (erreur failed to open umu.exe)

Dans un prefix Proton, les DLL de Wine sont des liens vers le runner. Ils doivent pointer en relatif dans runners/<nom>/ (ex. ../../../runners/<nom>/files/lib/wine/…). Un lien vers un autre emplacement est cassé ailleurs, et Proton ne le répare pas.

L'onglet « Dossiers » réécrit ces liens tout seul. Sur une image existante : fiche → Infos → Liens du runner → Analyser, puis la réparation proposée.

À la main : find MonJeu.wine -type l -lname '*compatibilitytools.d*' doit être vide.

Correctif du jeu dans le runner (protonfix)

Un Proton intégré peut porter un protonfix, script Python que Proton exécute avant chaque lancement. GAMEID désigne le script :

runners/<Proton>/protonfixes/gamefixes-umu/umu-monjeu.py
PROTON=<Proton>
ENV=GAMEID=umu-monjeu
  • main() fait la préparation (un sys.exit(1) arrête le lancement), puis peut lancer un fil pour le patch à chaud, qui vit jusqu'à la fin du jeu.
  • N'agir que si l'exécutable du jeu est dans sys.argv : umu sert aussi à d'autres commandes.
  • Pour tout runner, Wine compris : PRE= et ATTACH= de l'autorun.

L'essentiel

Manettes, langue, environnement

HIDRAWManette Sony gérée par le jeu lui-même1 · bt

Par défaut, la manette est vue comme une manette Xbox, comme sous Batocera. À changer seulement pour un jeu qui gère la DualSense lui-même (sans Steam Input) :

  • 1 : manette Sony par hidraw ; une DualSense Bluetooth est présentée en USB (dualsense-usb-bridge), car certains jeux refusent la Bluetooth. Repli en manette Xbox si illisible.
  • bt : DualSense Bluetooth en direct, pour un jeu dont les vibrations haptiques passent par la Bluetooth.

Sous GE-Proton, le mode manette Xbox passe aussi par hidraw (PROTON_SONY_HIDRAW_XINPUT=1, posé par le lanceur).

LANGLa langue du jeufr_FR.UTF-8
Posée dans LC_ALL.

Séparées par des espaces. Une surcharge ou un _defaults.autorun ajoute ses variables à celles de l'image au lieu de les remplacer ; -VAR en retire une, ENV= vide les retire toutes.

Touches clavier : un fichier <jeu>.wsquashfs.keys à côté de l'image associe des boutons de manette à des touches.

Avancé : commandes autour du jeu

Ces commandes s'exécutent sur le client, hors de Wine : seulement pour des images de confiance. Batocera et --exec les ignorent.
PREUne commande avant le jeush pre.sh
Lancée une fois, dans DIR, avec l'utilisateur et l'environnement du jeu (WINEPREFIX…). Un échec arrête le lancement. Sert à préparer des fichiers que l'image ne peut pas contenir tels quels.
ATTACHUne commande pendant le jeush attach.sh
Lancée une fois le processus du jeu trouvé ; GAME_PID contient son PID. Elle accompagne le jeu jusqu'à la fin de ses processus Wine, a ensuite 5 s pour finir, puis est arrêtée avec tout ce qu'elle a lancé.
ATTACH_PROCESSLe processus qu'attend ATTACHGame.exe
15 caractères au plus. Défaut : l'exécutable de CMD ; à renseigner quand CMD est un lanceur qui démarre le vrai jeu.

Pour aller plus loin

Essayer un réglage sans reconstruire (surcharge)

Un fichier <jeu>.wsquashfs.autorun à côté de l'image, au même format. Ses réglages l'emportent sur ceux de l'image ; RÉGLAGE= vide revient au défaut du lanceur. C'est ce qu'écrit « Essayer sans reconstruire ».

# Le Jeu.wsquashfs.autorun
HIDRAW=1

Batocera ne le lit pas : une fois le réglage validé, reconstruire l'image (ou « Inscrire les surcharges » sur une sélection).

Le lanceur lit aussi, du plus faible au plus fort : ~/.config/wsquashfs/defaults.autorun (le client), les variables WSQUASHFS_*, _defaults.autorun dans le dossier du jeu (tous les jeux du dossier), l'autorun.cmd de l'image, la surcharge, puis --set RÉGLAGE=valeur. wsquashfs-launcher --show donne la valeur finale de chaque réglage et sa provenance.

Choix automatique du runner

Sans WINE, PROTON, RUNNER, runner intégré ni --wine :

  • Prefix proton : la même version de Proton (Heroic, Steam, /usr/share/steam/compatibilitytools.d), sinon proton-cachyos, puis l'UMU-Proton le plus récent, puis GE-Proton, puis n'importe quel Proton. Lancé via umu, comme Heroic ; sans umu, le Wine du Proton est lancé directement (WSQUASHFS_UMU=0 force ce mode).
  • Aucun prefix (jeu seul) : proton-cachyos, sinon UMU-Proton, sinon GE-Proton. Les deux premiers gèrent la DualSense en manette Xbox avec vibrations ; GE-Proton la force en hidraw.
  • Autres prefixes (arcade Batocera) : wine-tkg, puis wine-ge/lutris, puis wine-proton, puis le Wine du système.

Les DLL que Proton copie d'ordinaire dans chaque prefix (~190 Mo par jeu) y sont des liens ; ENV=PROTON_DLL_COPY=<motifs> pour un jeu qui doit les remplacer. Le lanceur ramène la pile à 8 Mo si elle est illimitée (Docker sur Unraid), sans quoi proton-cachyos ne démarre pas.

Le lanceur

wsquashfs-launcher monte l'image et lance le jeu, sans aucun privilège. Le gestionnaire s'en sert ; tu peux aussi l'utiliser en ligne de commande.

Commandes

wsquashfs-launcher --help affiche l'essentiel et la version du lanceur ; tout le détail est ci-dessous.

wsquashfs-launcher <jeu.wsquashfs>Lancer le jeu.
--exec <jeu> <programme>Lancer un autre programme dans le prefix du jeu (winecfg, regedit, l'outil de config du jeu…).
--info <jeu>Version, type, runner, commande et taille, sans monter l'image.
--listLes jeux connus et leur état.
--syncSynchroniser les sauvegardes avec les autres clients (voir Sauvegardes).
--doctorVérifier l'installation (aussi dans le menu d'un client d'essai : « Diagnostic du lanceur »).
--updateMettre à jour le lanceur.
Toutes les commandes

Jouer

wsquashfs-launcher [--wine <runner>] [--set CLÉ=valeur]… <jeu.wsquashfs | dossier>
Lance le jeu. Un dossier .pc contenant autorun.cmd est essayé en overlay, comme son image, sans être modifié ; un autre dossier (.wine, jeu installé) est lancé sur place, sans montage.
--wine <runner>
Impose un runner (nom ou partie du nom, chemin d'un binaire wine, ou system), avant tout autre choix.
--set CLÉ=valeur
Réglage pour ce lancement seulement, plus fort que tous les fichiers ; répétable : --set NVAPI=0 --set ENV=DXVK_HUD=fps.
--exec <jeu.wsquashfs> <programme> [arguments…]
Exécutable du jeu (chemin relatif au prefix ou au DIR, casse ignorée) ou outil Wine (winecfg, regedit, cmd, explorer, control joy.cpl…). PRE/ATTACH ne sont pas lancés.
--prepare <jeu>
Prépare le prefix (création ou mise à jour, DXVK, VKD3D, NVAPI, registre) sans lancer le jeu.
--headless <jeu>
Lance le jeu dans gamescope sans écran (essai en arrière-plan).
--trial <jeu> [durée] [session NOM] [screenshot FICHIER]
Essai chronométré, utilisé par le lancement d'essai du gestionnaire : lance le jeu (60 s par défaut), observe ses processus et fenêtres, l'arrête et écrit un rapport JSON.
MangoHud, gamemode…
Se placent devant la commande : mangohud wsquashfs-launcher MonJeu.wsquashfs.

Images

--info <jeu> · --show <jeu> [--set CLÉ=valeur]…
Version, type de prefix, commande et taille ; réglages finaux et la couche d'où vient chacun (défauts, fichiers, autorun, surcharge, --set), emplacement des sauvegardes. Sans monter l'image.
--mount <jeu> · --umount [<jeu>]
Monter le jeu pour le modifier à la main (les changements vont dans ses sauvegardes) ; démonter un jeu ou tous.
--pack <Jeu.wine | Jeu.pc> [sortie.wsquashfs]
Crée une image (zstd). Une image existante n'est remplacée qu'une fois la nouvelle construite, après confirmation au terminal.
--install <jeu.wsquashfs> [dossier]
L'inverse de --pack : extrait le jeu pour jouer sans FUSE. L'image est conservée, un dossier existant n'est jamais écrasé.
--list
Jeux connus : état (en cours, monté), version, taille des sauvegardes et image.

Sauvegardes

--sync [jeu | status [jeu] | forget <machine> | wsq://…]
Synchronise à la main les sauvegardes avec les clients associés du réseau local. Sans argument : les jeux présents des deux côtés ; status montre ce qui serait fait. Conflit : la plus lourde gagne (à taille égale, la plus récente), l'autre est archivée. Jeu arrêté des deux côtés.
--sync dir · --sync dir add <nom> <chemin> · --sync dir forget <nom>
Dossiers synchronisés en plus des jeux (même nom sur chaque client, chemin à partir du dossier personnel) ; --sync dir les liste avec les jeux Switch d'Eden, synchronisés d'office jeu par jeu. Voir Sauvegardes.
--save <jeu> · --saves
Copie les sauvegardes de partie (Documents, Saved Games, AppData) d'un jeu, ou de tous, dans saves/<système>/<jeu> à côté de roms/. Sens unique, rien n'est supprimé. Restauration, jeu arrêté : cp -a saves/<système>/<jeu>/drive_c ~/.local/share/wsquashfs/saves/<jeu>/
--clean
Ménage sans risque : supprime le cache et les doublons des sauvegardes (fichiers recopiés sans modification). Ce que le jeu a écrit est gardé. Ne garde que les 3 dernières archives de --erase par jeu.
--clear [jeu]
Plus profond : ne garde que drive_c/users des sauvegardes, sans archive. Scores et réglages écrits ailleurs sont perdus.
--erase [jeu]
Efface toutes les sauvegardes : le jeu repart de son image. drive_c/users est archivé avant dans ~/.local/share/wsquashfs/backups/. Restauration : tar -xf <archive> -C ~/.local/share/wsquashfs/saves/<jeu>/

Clients et gestionnaire

--pair [roms DIR]… [port N]
Affiche le code d'association wsq://… (une seule fois, 10 min) à coller dans le gestionnaire (Associer un client, puis « Utiliser pour les essais » dans son menu) ou dans --sync wsq://… sur l'autre client, puis attend l'association.
--pair forget <machine> · --pair reset
Retire un client associé (son accès est coupé tout de suite) ; les retire toutes puis attend une nouvelle association.
--agent · --agent stop · --agent status
Lance l'agent en arrière-plan pour que le client reste joignable ; l'arrête ; dit s'il tourne et liste les clients associés. Rien ne le démarre tout seul. --agent run [log] : au premier plan, pour le débogage.

Installation

--doctor [json]
Vérifie FUSE, Wine/Proton et runners, umu, DXVK, VKD3D, d7vk, manettes, dossiers, et dit ce qui manque.
--update
Met à jour le lanceur depuis GitHub : affiche la version installée et la version distribuée ; le binaire est vérifié par sa somme SHA-256 avant remplacement.

Fonctionnement

Modes de montage

Choisis automatiquement à chaque lancement :

  • overlay noyau (par défaut) : overlay du noyau dans un namespace utilisateur ; lectures aléatoires environ 5 fois plus rapides, rien d'orphelin après un plantage. Requiert Linux ≥ 5.11 et squashfuse ≥ 0.5.
  • overlay FUSE (repli, et --mount) : squashfuse + fuse-overlayfs.
  • copy : FUSE bloqué (conteneur sans CAP_SYS_ADMIN) ; copie de travail en cache.
  • dossier : prefix .wine ou jeu installé par --install, lancé sur place. Un dossier .pc passe, lui, par l'overlay FUSE.

Tout échec de l'overlay noyau retombe sur fuse-overlayfs ; --doctor dit pourquoi. Les deux partagent les mêmes sauvegardes.

Où sont les données 
~/.local/share/wsquashfs/
├── saves/<jeu>/     ce que le jeu a écrit
└── wine/ dxvk/ …    runners et traducteurs installés
~/.cache/wsquashfs/  montages et copies de travail

À côté de l'image : <jeu>.wsquashfs.autorun (surcharge) et <jeu>.wsquashfs.keys (touches). À côté de roms/ : saves/<système>/<jeu>.

Variables d'environnement
WSQUASHFS_SAVES_DIR, WSQUASHFS_CACHE, WSQUASHFS_BACKUP_DIR
Emplacements des sauvegardes, du cache et des archives.
WSQUASHFS_BATOCERA_SAVES
Dossier de SAVEDIR/SAVEFILES (défaut : saves/ à côté de roms/).
WSQUASHFS_OVERLAY
auto (défaut), fuse ou kernel (sans repli).
WSQUASHFS_DXVK=0, WSQUASHFS_D7VK=0
Désactive DXVK ou d7vk pour tous les jeux (le réglage d'un jeu l'emporte).
WSQUASHFS_HIDRAW, WSQUASHFS_VIRTUAL_DESKTOP
Valeur par défaut de HIDRAW et VIRTUAL_DESKTOP pour tous les jeux.
WSQUASHFS_NVAPI, WSQUASHFS_VKREFLEX, WSQUASHFS_FSR, WSQUASHFS_FSR4
Valeur par défaut de NVAPI, VKREFLEX, FSR et FSR4 pour tous les jeux.
WSQUASHFS_UMU=0
Lance le Wine d'un Proton directement, sans umu.
WSQUASHFS_DXVK_DIR, WSQUASHFS_VKD3D_DIR, WSQUASHFS_D7VK_DLL
Emplacements de DXVK, VKD3D-Proton et d7vk.
Installer le lanceur sur un PC 
curl -fsSL https://raw.githubusercontent.com/Gunnm92/wsquashfs-launcher/main/install.sh | bash

Pour Debian/Ubuntu et Arch (CachyOS, Manjaro, EndeavourOS) : installe les paquets manquants, propose wine-tkg, umu-run et un Proton, DXVK, VKD3D-Proton et d7vk, puis termine par --doctor. Options : --dry-run, --yes, --uninstall. Le script ne fait que télécharger le lanceur s'il est absent : l'installation est faite par le lanceur lui-même (wsquashfs-launcher --setup), la mise à jour par --update.

Dépannage

Les problèmes fréquents et leur solution. Pour un jeu qui ne démarre pas, commence par le guide.

Le jeu ne se lance pas
Fiche → Lancement d'essai : rapport avec fenêtres, erreurs et capture. En ligne de commande : relancer depuis un terminal pour lire les erreurs Wine, et vérifier la commande avec --info.
failed to open umu.exe
Les liens du prefix pointent vers un runner absent. Fiche → Infos → Liens du runner → Analyser, puis la réparation proposée. Voir Runner intégré.
fusermount3: mount failed: Operation not permitted
FUSE est bloqué dans le conteneur : le lanceur passe en mode copy (plus lent au premier lancement). Pour l'overlay : --device /dev/fuse --cap-add SYS_ADMIN.
Overlay noyau indisponible
Le jeu marche quand même, sous fuse-overlayfs. --doctor donne la cause : squashfuse antérieur à 0.5 (Debian 12), namespaces refusés (seccomp de Docker : --security-opt seccomp=unconfined ; AppArmor d'Ubuntu 24.04 ; user.max_user_namespaces=0), ou sauvegardes sur un système de fichiers sans attributs user.*.
Make sure that your X server is running…
Wine ne trouve pas l'affichage : vérifier $DISPLAY et autoriser l'utilisateur avec xhost +SI:localuser:$(id -un).
Écran noir ou affichage très lent
Essayer DXVK=0 (vieux jeux Direct3D) ou VIRTUAL_DESKTOP=1920x1080 (jeu qui change la résolution), d'abord avec « Essayer sans reconstruire ».
Vieux jeu 32 bits qui plante au démarrage
wine-tkg n'est pas WoW64 : essayer WINE=system (le Wine WoW64 du système), éventuellement avec ARCH=win32.
Jeu arcade réseau : socket ICMP refusé (SOCK_RAW)
Le jeu vérifie la connexion par un « ping » que le conteneur refuse. Le relais fakeping (dinput8.dll) rend un ping sans réponse au lieu d'une erreur : sélectionner le jeu → Fichiers / registre → préréglage « relais fakeping ».
Un jeu reste monté
wsquashfs-launcher --umount démonte tous les jeux.
Repartir de zéro pour un jeu
Fiche → Réinitialiser les sauvegardes : elles sont mises de côté (renommées), pas supprimées. En ligne de commande : --erase "MonJeu" (archive drive_c/users, puis efface tout) ; --clear "MonJeu" ne garde que drive_c/users.
